# 노출 회복 대기 분리 — 실행 규칙 v9

2026-11-02. 사용자 승인에 따라 은신이 깨지기 전의 회복 시작만 늦춥니다. 노출 후 다시 숨는 과정은 기존 시간을 유지합니다. 상세 기획 v1.0 및 v7 중 회복 대기에 관해서는 아래 규칙을 우선합니다.

| 상태 | 이전 | 변경 |
| --- | --- | --- |
| 아직 은신 유지 중 | 마지막 위험 행동 후 2초 | 마지막 위험 행동 후 4초 |
| 한번 노출된 상태 | 마지막 위험 행동 후 2초 | 기존 2초 유지 |
| 감소 속도 | 초당 15 | 유지 |
| 다시 숨는 조건 | 노출 수치가 0에 도달 | 유지 |

## 적용 방식

현재 수치가 100인지 여부가 아니라 `Exposed` 상태로 대기를 선택합니다. 100에 도달해 노출됐다면 99, 80, 20으로 감소해도 0이 될 때까지 2초 대기 규칙을 유지합니다. 0으로 완전히 회복한 뒤 새로 쌓인 노출에는 4초 대기를 적용합니다.

기존 `LastDangerTick`을 공유합니다. 공격을 다시 승인받으면 해당 상태의 대기 시간이 다시 시작되고, 위험 행동을 한 Tick에는 감소하지 않습니다. 은신 중 실제 질주도 기존처럼 노출과 마지막 위험 시각을 갱신하므로 4초 대기를 적용합니다. 이미 노출된 상태에서 질주는 기본 설정상 노출 추가·대기 갱신을 하지 않는 v7 규칙을 유지합니다.

기본 설정에서 추가 위험 행동이 없을 때 근접 1회로 쌓인 35는 약 6.3초, 권총 1회로 쌓인 60은 약 8초 후 0으로 돌아옵니다. 이미 노출된 100은 기존처럼 약 8.7초가 기준입니다. Tick 단위 계산으로 소폭 차이가 있을 수 있습니다. NPC의 시야·추적 기억을 이 시간에 강제로 지우지는 않습니다.

대기를 분리하므로 높은 미노출 수치에서 100을 채우면 회복 시작이 앞당겨지는 경계 효과가 있습니다. 이는 제안 단계에서 설명한 상태 차이이며, 실제 유불리는 아직 플레이로 검증하지 않았습니다.

## 커스텀과 코드

활성 `GameSettings`의 Exposure 그룹에서 다음 항목을 조정합니다.

- `EXP_HIDDEN_DELAY`: 기본 4초, 아직 은신이 유지되는 동안의 대기.
- `EXP_DELAY`: 기존 2초, 노출 후 완전히 회복할 때까지의 대기. 기존 필드와 값을 유지하여 이전 커스텀 설정을 보존합니다.
- `EXP_DECAY`: 기존 15, 초당 감소량.

`CrowdRules.CanDecayExposure`에서 상태별 대기와 Tick 경계를 계산하고 `CrowdMatch`에서 사용합니다. 노출 증가량·상태 전환·감소량은 기존 `UpdateExposure`를 재사용합니다. 설정 자산은 접속 시 복제되므로 변경 후 새 세션을 시작해야 합니다.

규칙이 다른 클라이언트를 구분하기 위해 프로토콜은 `dead-crowd-development-9`입니다. 온라인 참가자는 모두 새 빌드를 사용합니다.

## 검증 범위

`DEAD CROWD > Development > Verify Exposure Recovery Rules`로 60/30 Hz에서 대기 경계, 미노출 중 대기, 100 도달, 100 미만으로 내려온 노출 상태, 0 회복, 위험 행동 우선을 검사합니다. 본 개발 Windows 빌드 과정에도 연결했습니다. 컴파일·규칙 검사·빌드 결과는 완료 보고에 기록하며 실제 플레이 및 온라인 회귀 QA는 이번 작업에서 진행하지 않습니다.

작업 검증 결과: Unity 컴파일, 기본 설정에서 노출 회복 규칙 검사 24개와 기존 후방 규칙 검사 11개, 저장된 UI 참조 검사, Windows Development 빌드가 성공했습니다. 로그는 `Logs/ExposureV9Build.log`, 실행 파일은 `Builds/Development/DEAD-CROWD.exe`입니다. 실제 플레이 체감과 네트워크 지연 환경은 미검증입니다.
