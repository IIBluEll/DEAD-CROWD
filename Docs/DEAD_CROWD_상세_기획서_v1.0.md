## 1. 게임 개요와 설계 목표

### 1.1 한 문장 설명

좀비 무리 속에서 상대 플레이어를 찾아내고, 정체가 드러날 위험을 관리하며 기습·총격으로 마지막까지 살아남는 3인칭 대전 게임입니다.

### 1.2 기본 구성

| 항목 | 내용 |
| --- | --- |
| 장르 | 군중 위장 기반 3인칭 PvP |
| 지원 모드 | 1vs1 / 4인 개인전 |
| 라운드 | 단판, 최후의 생존자 승리 |
| 전투 수단 | 근접 공격과 권총 |
| 기습 | 실제 타격 순간 후방이면 즉사 |
| 위험 관리 | 공격·질주로 노출 게이지 누적 |
| 환경 위협 | 노출된 플레이어를 발견한 좀비의 추격·공격 |
| 맵 | 작은 시가지 한 개, 광장·골목·건물 외곽 중심 |
| 온라인 접속 | 방 생성 및 초대 코드 입장 |

### 1.3 설계 목표

| 목표 | 플레이에서 나타나야 하는 선택 | 확인할 근거 |
| --- | --- | --- |
| 행동을 통한 식별 | 수상한 이동을 관찰하고 공격 여부 결정 | 플레이어가 의심의 근거를 설명할 수 있음 |
| 접근과 기습 | 상대를 알아낸 뒤 위치·몸 방향을 이용 | 정면 교전 외에 후방 접근 시도가 발생 |
| 행동의 위험 관리 | 한 번 더 공격할지, 물러나 노출을 낮출지 결정 | 게이지를 보고 행동을 바꾸는 사례 |
| 추격 후 재은신 | 질주로 벌린 거리와 시야 차단 경로 활용 | 추격 탈출이 가능하며 경로 선택 이유가 있음 |
| 판정의 납득 가능성 | 명중·빗나감·후방 피해의 이유 이해 | 화면·로그와 당사자 설명을 비교할 수 있음 |

이는 검증할 목표이며, 현재 재미가 입증됐다는 주장은 아닙니다. 첫 버전은 상용 서비스 운영, 장기 성장이나 콘텐츠 확장을 검증하는 단계가 아닙니다.

### 1.4 기본 플레이 순환

관찰 → 수동 위장 이동 → 상대 의심 → 접근·공격 → 노출 위험 판단 → 교전 지속 또는 도주 → 수색 회피 → 재접근을 반복합니다. 마지막 생존자가 되면 종료합니다.

## 2. 범위 및 제외 항목

### 2.1 필수 범위 — SCP-01

- 모드별 정원 방, 초대 코드, 준비·시작·종료·재경기
- 수동 이동, 질주, 자유 카메라, 조준과 몸 회전
- 플레이어와 NPC의 공통 외형·충돌·피격 기준
- 단일 대상 근접 공격, 일반 피해와 후방 즉사
- 권총 조준·발사·탄약·재장전·차단
- 행동 기반 노출 게이지, 노출 유지와 해제
- NPC 배회·조사·추격·공격·수색·복귀
- 체력, 사망, 관전, 최후 생존 승리와 무승부
- PC 두 대 이상 및 4인 환경에서 확인할 수 있는 네트워크 흐름

## 3. 용어와 공통 판정 기준

### 3.1 용어

| 용어 | 정의 |
| --- | --- |
| 호스트 | 게임 참가자이면서 최종 시뮬레이션과 판정을 수행하는 PC |
| 클라이언트 | 호스트에 접속해 입력을 보내고 결과를 표시하는 참가자 |
| 플레이어 | 사람이 조작하는 경기 참가 캐릭터 |
| NPC | 호스트 AI가 조작하는 좀비 캐릭터 |
| 생존자 | 사망·탈락하지 않은 플레이어. NPC는 생존 인원에 포함하지 않음 |
| 몸 방향 | 월드에 표시되는 캐릭터 몸의 수평 전방 방향 |
| 카메라 방향 | 본인의 시점 방향. 몸 방향과 다를 수 있음 |
| 노출 수치 | 플레이어별 0~100의 게이지 값 |
| 노출 상태 | 100 도달로 시작해 0 도달까지 유지되는 추격 가능 상태 |
| 추격 기억 | 특정 NPC가 기존에 발견한 대상의 신원과 마지막 목격 위치 |
| Tick | 호스트 시뮬레이션의 한 판정 단위 |
| 공격 성립 | 입력·상태·자원 조건을 통과해 호스트가 실행을 승인한 상태 |

### 3.2 공간·시간 — COM-01

- 1 Unity 월드 단위를 1m로 취급합니다. 맵은 수평 지면을 기준으로 설계합니다.
- 수평 거리·각도는 지면에 투영한 위치와 몸 방향을 사용합니다. 권총·시야의 차단은 실제 3D 경로로 검사합니다.
- 캐릭터 위치 기준점은 지면의 몸 중심입니다. 근접 사거리도 두 기준점 사이 수평 거리입니다.
- 선딜레이·주기·라운드 시간은 호스트 Tick으로 판정합니다. 화면 FPS나 애니메이션 이벤트가 최종 타격 시각을 바꾸지 않습니다.
- 초 단위 시간은 해당 시간 이상을 만족하는 가장 빠른 Tick에 완료합니다. 초기 60Hz에서 0.3초는 18 Tick입니다.
- 클라이언트 화면의 카운트다운과 게이지는 호스트 원본 상태를 표시하며 승패를 독자 확정하지 않습니다.

### 3.3 충돌·피격 공통 기준 — COM-02

플레이어와 NPC는 동일한 크기의 몸 충돌과 피격용 몸통 캡슐을 사용합니다. 모델의 손·무기·머리 장식 유무로 판정 크기가 달라지지 않습니다. 본인 몸은 자신의 공격 검사에서 제외합니다.

살아 있는 캐릭터는 이동을 막고 탄환과 근접 차단의 대상이 됩니다. 시체는 이동·공격을 막지 않습니다. 맵의 벽·건물은 이동·공격·NPC 시야·카메라를 막습니다. 바닥과 장식물의 각 차단 여부는 맵 제작 시 명시합니다.

피해·노출·탄약을 클라이언트가 임의로 결정하는 요청은 받지 않습니다. 이후 절의 '적용'은 호스트 확정을 뜻합니다.

## 4. 방 생성·입장·준비

### 4.1 접속 방식 — LOB-01

첫 버전은 비공개 방 생성과 초대 코드 입장만 지원합니다. 공개 방 목록과 자동 매칭 대기열은 없습니다. 초대 코드는 해당 방을 찾기 위한 정보이며 별도 계정 로그인을 요구하지 않습니다.

방 생성자가 호스트가 되고 모드를 선택합니다. 방 정원은 호스트를 포함해 1vs1은 2명, 4인전은 4명입니다. 방을 만든 뒤 모드는 변경하지 않으며 다른 모드를 원하면 새 방을 만듭니다.

초기 개발 빌드는 모든 참가자가 동일한 Photon 접속 리전 설정을 사용합니다. 리전 자동 선택 차이로 같은 코드가 다른 방을 가리키지 않도록 합니다. 실제 리전·AppId·SDK 버전은 개발 환경 명세에 고정하고, v1.0에서는 리전 선택 UI와 다중 리전 검색을 만들지 않습니다.

### 4.2 초대 코드 — LOB-02

| 항목 | 규칙 |
| --- | --- |
| 초기 형식 | 영문 대문자·숫자 6자리, 혼동 문자 I·O·0·1 제외 |
| 생성 | 호스트가 방을 만들 때 생성, 기존 활성 코드와 충돌하면 재생성 |
| 정규화 | 입력 앞뒤 공백 제거, 소문자는 대문자로 변환 |
| 오류 | 길이·문자 오류는 접속 요청 전에 안내 |
| 공유 | 대기실에 코드 표시 및 복사 버튼 제공 |
| 유효 기간 | 호스트가 방을 유지하는 동안, 재경기에도 같은 코드 유지 |
| 종료 | 호스트가 방을 닫으면 코드도 사용할 수 없음 |

코드 생성·충돌 확인은 방 생성 절차로 처리하며 코드별 별도 백엔드 DB를 필수로 만들지 않습니다. 생성·연결 시도 횟수와 제한 시간은 초기 데이터 표를 사용합니다.

### 4.3 입장과 준비 — LOB-03

1. 참가자가 코드를 입력하고 입장을 요청합니다.
2. 존재 여부, 정원, 방 상태, 호환 빌드 여부를 확인합니다.
3. 성공하면 빈 참가 슬롯에 배치하고 대기실을 표시합니다.
4. 참가자별 준비 상태를 표시합니다. 슬롯 번호는 라운드 중 실제 캐릭터의 머리 위에 표시하지 않습니다.
5. 정원 충족 및 전원 준비 상태에서만 호스트의 시작 버튼을 활성화합니다.

전원 준비만으로 자동 시작하지 않습니다. 호스트도 준비 대상이며 직접 시작을 선택합니다. 참가자 추가·이탈 시 기존 준비 상태를 모두 해제해 변경된 구성으로 다시 확인합니다.

| 대기실 | 코드 공유·입장·준비·나가기 | 정원·전원 준비 후 호스트 시작 → 로딩 |
| 로딩 | 맵·공통 설정 로드, 준비 완료 응답 | 전원 준비 → 시작 대기 |
| 시작 대기 | 카메라 관찰만 허용 | 카운트다운 완료 → 전투 |
| 전투 | 생존자의 이동·전투, 사망자의 관전 | 종료 조건 성립 → 결과 확정 |
| 결과 확정 | 최종 피해 결산과 승패 한 번 확정 | 결과 동기화 → 결과 화면 |
| 결과 화면 | 결과 확인·대기실 복귀·나가기 | 호스트가 대기실 복귀 → 대기실 |
| 세션 중단 | 사유 표시·타이틀 복귀 | 새 방 생성 또는 입장 |

로딩부터 결과 화면까지 외부의 새 참가자 입장을 막습니다. 대기실로 돌아온 뒤에는 빈 슬롯을 채울 수 있습니다. 모드 정원을 다시 만족해야 다음 판을 시작합니다.

### 5.2 로딩과 시작 — MAT-02

호스트가 맵·설정 버전과 배치 Seed를 정하고 NPC·플레이어를 준비합니다. 전원이 로드 완료해야 카운트다운을 시작합니다. 시작 위치는 제13절의 승인된 조합에서 정합니다.

카운트다운 중에는 이동·공격·재장전·노출·피해를 진행하지 않습니다. NPC도 배치된 상태로 정지합니다. 카메라 관찰만 가능합니다. 카운트다운 종료 Tick을 전투 시작 Tick으로 삼고 제한 시간을 계산합니다.

로딩·시작 대기에서 참가자가 이탈하면 시작을 취소합니다. 로드 실패·제한 시간 초과 참가자는 오류를 안내하고 방 연결을 정리해 타이틀로 이동하며, 남은 참가자는 대기실로 복귀합니다. 호스트 자체가 로드에 실패하면 전체 세션을 중단합니다. 맵 로드 실패는 결과 승패가 아니라 시작 실패로 처리합니다.

### 5.3 승패 — MAT-03

- 전투 중 살아 있는 플레이어가 한 명이면 그 플레이어가 승리합니다.
- 플레이어를 누가 처치했는지는 생존 승리에 영향을 주지 않습니다. 좀비 피해로 경쟁자가 사망해도 같습니다.
- 한 Tick의 유효 피해를 함께 결산한 결과 생존자가 0명이면 전멸 무승부입니다.
- 제한 시간 경계 Tick까지의 유효 피해를 결산한 뒤 생존자가 두 명 이상이면 시간 초과 무승부입니다.
- 시간 초과 때 체력·처치 수·노출 수치로 순위를 정하지 않습니다.
- 경기 결과를 확정한 뒤 추가 피해나 중복 승리 처리를 하지 않습니다.

### 5.4 사망·접속 종료 — MAT-04

사망자는 조작권을 잃고 라운드가 끝날 때까지 부활하지 않습니다. 일반 참가자의 명시적인 나가기는 즉시 탈락 처리합니다. 네트워크 유실은 제18절의 연결 종료 기준으로 처리합니다.

**호스트가 캐릭터로 사망해도 호스트 역할은 계속 수행합니다.** 관전 중에도 NPC·피해·승패 시뮬레이션을 중단하지 않습니다. 호스트가 방을 나가거나 호스트 연결이 끊기면 전체 세션을 중단하고 승자를 임의로 만들지 않습니다.

### 5.5 재경기 — MAT-05

결과 화면에서 호스트가 대기실 복귀를 선택하면 연결된 참가자들이 함께 돌아갑니다. 준비 상태는 모두 해제합니다. 다음 시작에는 체력·탄약·노출·AI 기억·시체·타이머·처치 기록을 초기화하고 배치를 다시 선택합니다.

코드와 방 모드는 유지합니다. 한 판의 승리를 다음 판 장비·능력에 누적하지 않습니다.

## 6. 캐릭터·체력·외형

### 6.1 캐릭터 구성 — CHR-01

모든 플레이어는 같은 성능의 캐릭터, 근접 무기와 권총으로 시작합니다. NPC도 같은 체력·몸 크기·일반 보행 속도 기준을 사용합니다. 외형을 변형하더라도 플레이어만 사용하는 외형을 만들지 않습니다.

평상시 무기는 보이지 않게 합니다. 공격·조준·발사·재장전에는 필요한 무기와 자세를 보여주며, 다른 사람이 이를 보고 정체를 알아내는 것은 허용합니다. 행동 종료 후 평상시 자세로 돌아가도 이미 관찰한 상대의 기억을 지우지 않습니다.

### 6.2 체력과 피해 — CHR-02

- 최대 체력과 시작 체력은 동일하며, 플레이어·NPC 모두 같은 초기값을 사용합니다.
- 피해는 현재 체력에서 차감하며 0 이하에서 사망합니다. 표시 체력은 0 아래로 내려가지 않습니다.
- 자연 회복·회복 아이템·방어구·치명타 확률·헤드샷 보너스·피격 후 무적은 없습니다.
- 피격 모션과 소리는 제공하되 입력·이동·진행 중 공격을 막는 피격 경직은 없습니다.
- 피해를 받는 것 자체는 노출 게이지를 올리지 않습니다.
- 서로 다른 공격의 피해는 중복 적용될 수 있습니다. 같은 공격 인스턴스의 중복 피해는 막습니다.

### 6.3 사망과 시체 — CHR-03

사망 시 이동·공격·조준·재장전을 중단하고 몸 충돌과 피격 판정을 해제합니다. 이후 타격 시점이 도래하는 미완료 공격은 실행하지 않습니다. 같은 Tick에 성립한 공격의 동시 결산은 제16절을 따릅니다.

시체는 정해진 시간 동안 표시한 뒤 제거합니다. 플레이어·NPC의 시체 유지 시간, 기본 모션과 효과는 같습니다. 시체에 추가 피해·처치·소음 조사를 반복 발생시키지 않습니다. 시체는 공격·탄환을 막지 않습니다.

NPC도 해당 판에서 재생성하지 않습니다. NPC 감소는 위장 환경의 변화로 기록하며 자동 충원하지 않습니다.

## 7. 입력·이동·행동 제약

### 7.1 기본 입력 — CTL-01

| 입력 | 기능 | 판정 방식 |
| --- | --- | --- |
| W/A/S/D | 이동 | 카메라 수평 방향 기준, 대각선 입력 크기 정규화 |
| 마우스 이동 | 카메라 회전 | 몸 회전과 분리, 제8절 적용 |
| 왼쪽 Shift 유지 | 질주 | 이동 중이며 다른 행동 제약이 없을 때 |
| 마우스 오른쪽 버튼 유지 | 권총 조준 | 조준 가능한 상태에서 유지 |
| 마우스 왼쪽 버튼 누름 | 공격 | 조준 의도 있으면 권총, 없으면 근접 |
| R 누름 | 재장전 | 탄창이 비어 있거나 덜 찼고 예비 탄약이 있을 때 |
| Esc | 메뉴 | 방 나가기·설정 접근, 온라인 경기 시간은 계속 흐름 |
| 관전 중 A/D | 관전 대상 전환 | 관전자 입력에서만 처리 |

공격은 버튼을 새로 누른 입력마다 한 번 시도합니다. 길게 누르고 있어도 근접·권총을 반복 실행하지 않습니다. 실행할 수 없는 공격을 다음 상태로 예약하지 않으며, 실행하려면 다시 눌러야 합니다.

초기 입력 변경 UI와 패드는 범위 밖입니다. 카메라 감도·음량 조절은 로컬 설정으로 제공합니다. 메뉴를 연 동안 본인 전투 입력은 중립 처리하되 무적이나 경기 일시정지는 제공하지 않습니다.

### 7.2 몸 방향과 이동 — CTL-02

- 비조준 이동: 이동 방향으로 최대 회전 속도 안에서 몸을 돌립니다. 카메라 기준 옆 이동도 몸이 이동 방향을 따라갑니다.
- 비조준 정지: 마지막 몸 방향을 유지합니다. 카메라를 돌리는 것만으로 몸이 바뀌지 않습니다.
- 조준 이동·정지: 몸이 카메라의 수평 조준 방향을 따릅니다. 이동은 카메라 기준으로 가능하며 조준 속도를 적용합니다.
- 근접 공격 중: 이동 입력으로 몸을 돌릴 수 있으나 공격 중 회전 상한과 감속을 적용합니다. 이동 입력이 없으면 카메라 회전만으로 공격 방향을 바꾸지 않습니다.
- 질주 중: 질주 속도와 일반 몸 회전 상한을 적용합니다. 전투 행동이 성립하면 질주를 종료합니다.

이동 속도는 상태별 상한이며 대각선·프레임 수·클라이언트 임의 값으로 더 빨라지지 않습니다. 경사는 첫 맵의 수평 이동을 해치지 않는 범위만 사용하며 계단·다층 이동은 맵 범위 밖입니다.

### 7.3 행동 상태 — CTL-03

| 상태 | 이동 | 몸 회전 | 허용 전투 행동 | 종료 |
| --- | --- | --- | --- | --- |
| 일반 | 보행 또는 질주 | 일반 상한 | 근접·조준·재장전 시작 | 새 행동 성립 |
| 조준 | 조준 속도 | 조준 방향 추종 | 정렬 후 발사·재장전 | 조준 버튼 해제·재장전·사망 |
| 근접 진행 | 근접 감속 | 공격 중 상한 | 추가 행동 불가 | 전체 공격 주기 종료 |
| 발사 후딜 | 조준 유지 시 조준 속도, 해제 시 보행 | 해당 조준 의도에 따름 | 추가 발사·근접·재장전·질주 불가 | 발사 간격 완료 |
| 재장전 | 보행 | 이동 방향 추종 | 다른 전투 행동·질주 불가 | 재장전 완료 |
| 사망 | 불가 | 조작 불가 | 불가 | 라운드 재시작 |

조준 종료만으로 발사 후딜을 취소하지 않습니다. 발사 후딜이 끝났을 때 조준 버튼이 유지 중이면 조준, 아니면 일반 상태가 됩니다. 근접과 재장전도 자발적으로 취소하지 않습니다.

### 7.4 같은 Tick의 입력 우선순위 — CTL-04

1. 사망·라운드 비활성·메뉴 입력 차단을 먼저 적용합니다.
2. 이미 진행 중인 근접·발사 후딜·재장전의 제약을 적용합니다.
3. 일반·조준 상태에서 유효한 재장전 입력을 공격보다 우선합니다. 실행 불가능한 재장전은 다른 유효 입력을 막지 않습니다.
4. 조준 버튼의 현재 상태로 공격 종류를 결정합니다. 오른쪽 버튼과 왼쪽 버튼을 동시에 누르면 조준 발사를 시도합니다.
5. 공격이 없으면 조준·일반 이동·질주를 갱신합니다. 조준과 질주를 함께 유지하면 조준을 우선합니다.

조준 발사가 정렬·탄약 조건을 충족하지 못했다고 근접 공격으로 대체하지 않습니다. 근접을 하려면 조준 버튼을 놓고 새 공격 입력을 보냅니다.

## 8. 카메라·조준 정렬

### 8.1 카메라 — CAM-01

캐릭터를 따라가는 3인칭 카메라를 사용합니다. 일반·질주·조준에서 사용자는 주변을 회전 관찰할 수 있습니다. 카메라만 뒤를 봐도 캐릭터 몸이 뒤를 보는 것은 아닙니다.

카메라는 벽·건물과 충돌하면 캐릭터 쪽으로 당겨져 벽 내부나 너머로 통과하지 않습니다. 캐릭터 자신과 다른 캐릭터 때문에 카메라 거리를 매번 줄이지는 않습니다. 카메라 조준점은 화면 중앙을 사용합니다.

기본 거리·시야각·조준 거리·상하 회전 한계는 초기값입니다. 조준 확대는 카메라 구도 변화이며 총의 사거리·피해를 바꾸지 않습니다. 상대의 후방 여부는 항상 몸 방향으로 판단합니다.

### 8.2 정렬 후 발사 — CAM-02

사용자 결정에 따라 몸이 조준 방향을 따라가지 못한 동안은 발사를 허용하지 않습니다.

- 몸 수평 전방과 카메라 수평 조준 방향의 각도 차이가 정렬 허용 오차 이하면 발사 가능합니다.
- 오차를 넘는 동안 조준점에 정렬 중 상태를 표시합니다. 탄약을 소비하거나 발사 소리·노출을 발생시키지 않습니다.
- 이때 누른 공격 입력을 저장해 정렬 완료 후 자동 발사하지 않습니다. 정렬 후 새 입력이 필요합니다.
- 정렬 여부는 클라이언트가 예측 표시할 수 있지만 최종 발사 승인은 호스트가 판단합니다.
- 정렬 조건은 수평 몸 회전을 대상으로 합니다. 상하 조준은 카메라 피치와 총구 표현으로 처리합니다.

조준만으로는 노출 증가와 감소 대기 갱신이 없습니다. 조준 자세는 다른 플레이어에게 식별 단서가 될 수 있습니다.

## 9. 근접 공격

### 9.1 규칙 — MEL-01

일반·후방 공격은 같은 버튼·모션·사거리·선딜레이·주기를 사용합니다. 실제 타격 순간 대상 몸 방향에 따라 피해만 다릅니다. 별도 암살 조건·상호작용·연출은 없습니다.

공격은 한 번에 살아 있는 대상 한 명에게만 적용합니다. 플레이어·NPC를 구분해서 표적 우선순위를 주지 않습니다.

### 9.2 시간과 비용 — MEL-02

1. 호스트가 입력·상태를 확인해 공격을 승인하고 시작 Tick·공격 ID를 기록합니다.
2. 시작 시 노출 증가와 휘두르기 소음을 각각 한 번 발생시킵니다.
3. 선딜레이가 완료된 Tick에 한 번만 명중 검사를 수행합니다.
4. 유효한 대상이 있으면 피해·명중 소음·효과를 발생시킵니다.
5. 공격 시작부터 전체 주기가 완료될 때 다음 행동을 허용합니다.

전체 주기는 선딜레이를 포함합니다. 초기값 기준 시작 후 0.3초에 타격하고 시작 후 0.85초에 행동 잠금을 해제합니다. 빗나가거나 장애물에 막혀도 비용과 잠금을 되돌리지 않습니다. 명중 시 노출을 추가로 한 번 더 올리지 않습니다.

### 9.3 부채꼴 대상 선정 — MEL-03

사용자 결정에 따라 애니메이션의 무기 궤적을 최종 명중 기준으로 사용하지 않습니다. 타격 Tick의 전방 부채꼴을 기준으로 아래 순서를 적용합니다.

1. 공격자·대상의 지면 기준점 사이 수평 거리가 사거리 이내인 살아 있는 캐릭터를 수집합니다.
2. 공격자 몸 전방과 대상 방향의 수평 각도가 전방 반각 이내인 후보만 남깁니다. 거리·각도 경계값은 포함합니다.
3. 공격자 몸통 중심에서 후보 몸통 중심까지의 경로를 검사합니다. 벽·지형·다른 살아 있는 몸에 막힌 후보는 제외합니다.
4. 남은 후보 중 수평 거리가 가장 가까운 한 명을 선정합니다. 거리가 같으면 해당 라운드의 안정적인 캐릭터 생성 ID가 작은 대상을 선택합니다.
5. 후보가 없으면 빗나감입니다. 몸만 겹쳐 방향을 정할 수 없는 잘못된 배치는 생성·이동 충돌 단계에서 막습니다.

앞 NPC가 경로를 막으면 뒤의 플레이어는 후보에서 제외됩니다. 앞 NPC가 사거리·각도 조건을 충족하면 그 NPC를 타격할 수 있습니다. 시체는 후보와 차단 검사에서 제외합니다.

### 9.4 후방 방향과 피해 — MEL-04

명중 대상을 정한 동일 Tick에 대상 몸 전방과 대상에서 공격자로 향하는 방향을 비교합니다. 대상 정후방의 좌우 후방 반각 이내면 후방 피해를 적용하고, 그 밖은 일반 피해입니다.

초기 기준은 정후방 ±50도입니다. 대상 전방 기준으로 표현하면 공격자가 130~180도에 있을 때 후방이며 130도 경계도 포함합니다. 카메라 방향, 입력 당시 방향, 무기가 닿는 시각적 위치는 이 판정을 바꾸지 않습니다.

후방 명중은 플레이어·NPC 모두 즉사입니다. 최대 체력을 바꿀 때 후방 즉사 조건을 함께 유지합니다. 전투 중·노출 중이어도 후방 즉사는 성립하며, 타격 전에 돌아서 범위를 벗어나면 일반 피해입니다.

## 10. 권총

### 10.1 발사 승인 — GUN-01

다음 조건을 모두 충족해야 발사합니다.

- 전투 중 살아 있는 플레이어이며 다른 행동 잠금이 없음
- 조준 버튼 유지, 몸 정렬 조건 충족
- 발사 후딜 종료 및 탄창 탄약 한 발 이상
- 동일 입력에 대한 발사를 이전에 확정하지 않음

승인 시 탄약 한 발 소비, 발사 노출, 총성, 발사 후딜을 각각 한 번 적용합니다. 실패 입력은 탄약·노출·총성을 발생시키지 않습니다. 탄약 없음·정렬 중·재장전 상태는 UI로 구분합니다.

### 10.2 명중과 차단 — GUN-02

권총은 발사 Tick에 명중을 검사하는 히트스캔 방식입니다. 움직이는 물리 탄환·관통·산탄·확률 탄퍼짐·거리 피해 감소·머리 추가 피해는 없습니다. 반자동이며 새 클릭마다 한 발입니다.

1. 카메라 중앙 광선이 처음 만나는 대상·지형을 조준점으로 삼습니다. 아무것도 없으면 카메라 정면의 충분히 먼 점을 사용합니다.
2. 캐릭터 몸통 중심에서 논리 총구까지 벽·지형·다른 살아 있는 몸을 검사합니다. 벽·지형이 먼저 막으면 발사는 성립하되 캐릭터 피해는 없습니다. 다른 살아 있는 몸이 먼저 막으면 그 캐릭터에게만 피해를 적용하고 검사를 끝냅니다.
3. 위 경로가 비어 있으면 총구에서 조준점 방향으로 권총 사거리만큼 검사합니다. 처음 만난 벽·지형·살아 있는 캐릭터에서 멈춥니다.
4. 캐릭터라면 공통 권총 피해를 적용합니다. NPC가 앞에 있거나 총구가 NPC 몸 안으로 들어간 상황에서도 그 NPC를 건너뛰고 뒤 플레이어를 맞히지 않습니다. 경로 검사는 시작점이 차단물 안에 있는 경우도 포함해야 합니다.

자신의 몸과 시체는 발사 검사에서 제외합니다. 맞지 않았거나 벽에 막혀도 이미 성립한 발사의 탄약·노출·후딜은 유지합니다. 카메라가 볼 수 있다는 이유만으로 총구 앞 장애물을 무시하지 않습니다.

### 10.3 재장전 — GUN-03

탄창이 덜 찼고 예비 탄약이 있을 때 시작할 수 있습니다. 탄창이 가득 찼거나 예비 탄약이 없으면 시작하지 않습니다. 시작 시 조준을 해제하고 재장전 잠금을 적용합니다.

완료 시 `필요 탄약 = 탄창 용량 - 현재 탄창`을 계산하고, 필요 탄약과 예비 탄약 중 적은 양을 옮깁니다. 남은 탄창 탄약을 버리지는 않습니다. 사망·라운드 종료로 중단되면 탄약 이동을 하지 않습니다.

자동 재장전·탄약 보급·무기 획득은 없습니다. 탄약이 소진돼도 근접 공격은 가능합니다. 재장전 자체는 노출을 올리거나 감소 대기를 갱신하지 않습니다.

## 11. 노출 게이지

### 11.1 수치와 상태 — EXP-01

플레이어마다 노출 수치 E와 노출 상태를 구분합니다. E는 0~100 범위입니다. 노출은 상대 플레이어가 정체를 알고 있는지를 의미하지 않으며 NPC 신규 추격 조건입니다.

| 이전 상태 | 조건 | 다음 상태 |
| --- | --- | --- |
| 비노출 | E가 100 미만 | 비노출 유지 |
| 비노출 | E가 100 도달 | 노출 진입 |
| 노출 | E가 0보다 큼 | 노출 유지 |
| 노출 | E가 0 도달 | 비노출 복귀 |
| 어느 상태든 | 사망·라운드 종료 | 갱신 중단 |

100 이후 99로 감소해도 노출은 유지합니다. 100에 도달하기 전이라도 위험 행동을 멈추면 감소할 수 있습니다.

### 11.2 행동별 증가 — EXP-02

| 행동 | 증가 시점 | 최초 설정 참조 |
| --- | --- | --- |
| 근접 공격 | 공격 승인 시 한 번, 명중 여부 무관 | EXP_MELEE_ADD |
| 질주 | 실제 질주 이동 시간에 비례 | EXP_SPRINT_PER_SEC |
| 권총 | 발사 승인 시 한 번 | EXP_SHOT_ADD |
| 일반 보행·정지·카메라 회전 | 증가 없음 | 0 |
| 조준·재장전·피격 자체 | 증가와 감소 대기 갱신 없음 | 0 |
| 거부된 공격·빈 탄창 클릭 | 증가 없음 | 0 |

공격 대상의 정체·피해량·처치 여부는 증가량을 바꾸지 않습니다. 질주 키만 누르고 이동하지 못하는 상황은 질주 시간으로 누적하지 않습니다. 현재 이동이 질주 속도 상태이고 실제 수평 변위가 발생한 시간을 누적합니다.

### 11.3 감소 — EXP-03

근접·발사 승인 또는 실제 질주가 발생할 때 마지막 위험 행동 시간을 갱신합니다. 질주는 지속하는 동안 매 Tick 갱신합니다.

위험 행동 없이 감소 대기 시간이 지나면 초당 감소량을 적용합니다. 같은 Tick에 위험 행동이 있으면 증가·대기 갱신이 우선이며 감소는 없습니다. E는 0~100으로 제한하고 초과분은 저장하지 않습니다.

100에서 계속 공격·질주하면 감소가 시작되지 않습니다. 조준만 유지하거나 재장전하는 동안에는 다른 위험 행동이 없으면 감소할 수 있습니다.

### 11.4 기존 추격과의 관계 — EXP-04

비노출 상태의 플레이어는 새 좀비에게 직접 보이더라도 신규 추격 대상이 되지 않습니다. 소음 위치 조사는 별도로 발생합니다.

이미 대상을 발견한 NPC는 노출이 해제돼도 추격 기억을 즉시 지우지 않습니다. 시야가 유지되면 추격하고, 시야를 잃으면 마지막 위치를 수색합니다. 수색 중 같은 대상을 다시 직접 보면 노출 수치와 관계없이 추격을 재개할 수 있습니다.

수색을 끝내고 기억을 해제한 NPC는 다시 공통 신규 추격 조건을 따릅니다. 맵 전체 좀비가 대상 기억을 공유하지 않습니다.

### 11.5 초기값의 해석

공격 간 감소가 없다는 조건에서 근접 세 번은 105를 100으로 제한해 노출됩니다. 권총 두 발은 120을 100으로 제한합니다. 근접 한 번과 권총 한 발은 95이며 아직 비노출입니다.

게이지 0에서 질주만 지속하면 약 5초에 노출됩니다. 100에서 위험 행동을 멈추면 2초 대기 후 초당 15씩 감소해 약 8.7초 뒤 노출이 해제됩니다. 이 시간은 기존 NPC의 추격 종료를 보장하지 않습니다.

## 12. NPC 좀비

### 12.1 공통 원칙 — AI-01

NPC AI의 상태·난수·이동 목표·추격 대상과 공격은 호스트에서 결정합니다. 다른 클라이언트는 동기화된 상태를 표시합니다. NPC도 플레이어와 같은 체력·피격·시체·몸 충돌 기준을 사용합니다.

NPC는 다른 NPC를 공격하지 않습니다. 피격한 NPC도 공격자를 무조건 반격하는 예외는 없으며, 노출·직접 시야·기존 추격 기억으로 판단합니다.

### 12.2 상태와 전환 — AI-02

| 상태 | 진입 시 정보 | 행동 | 종료·전환 |
| --- | --- | --- | --- |
| 대기 | 대기 종료 시각 | 정지하고 몸 방향 유지 | 시간 완료 → 배회, 소음 → 조사, 노출 대상 발견 → 추격 |
| 배회 | 도달 가능한 이동 목표 | 공통 보행 속도로 이동 | 도착 → 대기, 소음 → 조사, 노출 대상 발견 → 추격 |
| 조사 이동 | 마지막으로 들은 소음 위치 | 위치까지 이동 | 도착 → 조사 대기, 이동 실패 제한 → 조사 대기, 노출 대상 발견 → 추격 |
| 조사 대기 | 조사 종료 시각 | 도착 위치에서 주변 확인 | 시간 완료 → 대기, 새 소음 → 조사 이동, 노출 대상 발견 → 추격 |
| 추격 | 대상 ID와 마지막 목격 위치 | 대상이 직접 보이는 동안 위치 갱신·추적 | 공격 조건 충족 → 공격, 시야 상실 → 수색 이동 |
| 공격 | 대상 ID·타격 Tick·종료 Tick | 몸을 대상 쪽으로 돌리며 선딜레이 후 한 번 타격 | 주기 종료 후 시야 있으면 추격, 없으면 수색 |
| 수색 이동 | 대상 ID·마지막 목격 위치 | 마지막 위치까지 이동 | 도착·이동 실패 제한 → 수색 대기, 기억한 대상 재발견 → 추격 |
| 수색 대기 | 대상 ID·수색 종료 시각 | 마지막 위치 부근에서 주변 확인 | 재발견 → 추격, 시간 완료 → 기억 해제 후 대기 |
| 사망 | 사망 Tick | 충돌 해제·시체 표시 | 유지 시간 완료 → 제거 |

시야 확인과 상태 전환은 매 호스트 Tick에 평가합니다. 주변 확인은 제자리에서 정해진 회전 상한 안에 몸을 돌려 전방 시야를 바꾸는 방식이며, 벽 너머 360도 탐지를 제공하지 않습니다.

### 12.3 배회 — AI-03

배회 지점 도착 후 대기 시간 범위에서 호스트 난수로 시간을 선택합니다. 대기가 끝나면 현재 위치 주변의 도달 가능한 지점을 선택합니다. 목표는 배회 거리 범위에 있고 벽·몸과 겹치지 않아야 합니다.

정해진 횟수 안에 목표를 찾지 못하면 짧게 대기한 후 다시 시도합니다. 이동 경로가 막히거나 제한 시간 동안 진행하지 못해도 같은 절차로 새 지점을 선택합니다. 다른 NPC를 통과하거나 순간이동해 해결하지 않습니다.

NPC 난수 Seed와 맵·설정 버전을 기록합니다. Seed만으로 Unity 경로·물리 결과까지 모든 환경에서 완전히 재현된다고 보장하지는 않습니다.

### 12.4 시야 — AI-04

신규 대상 발견에는 다음 조건이 모두 필요합니다.

1. 대상이 살아 있는 플레이어이며 노출 상태입니다.
2. NPC와 대상 기준점 사이 거리가 시야 거리 이내입니다.
3. NPC 몸 전방과 대상 수평 방향의 각도가 시야 반각 이내입니다.
4. NPC 눈 위치에서 대상 몸통 중심까지 벽·지형에 가리지 않습니다.

다른 캐릭터 몸은 NPC 시야의 차단물로 사용하지 않습니다. 군중 안에 들어갔다는 이유만으로 이미 발견한 대상이 즉시 사라지지는 않습니다. 같은 시야 거리·각도 기준을 기존 대상의 직접 재발견에도 사용합니다.

같은 Tick에 여러 신규 노출 대상을 발견하면 가장 가까운 대상을 택합니다. 거리 동률은 안정적인 캐릭터 ID 순서로 처리합니다. 추격 중에는 다른 가까운 대상을 보더라도 기존 대상을 우선 유지합니다.

### 12.5 소음 — AI-05

근접 시작·근접 명중·권총 발사는 서로 다른 범위의 소음 사건입니다. 소음에는 발생 위치·시각만 주며 공격자 현재 위치를 계속 전달하지 않습니다.

범위 안 NPC는 벽 너머 소음도 인지할 수 있습니다. 벽 재질별 감쇠와 실내 잔향에 따른 AI 계산은 없습니다. 배회·대기·조사 중 새 소음을 들으면 최근 소음 위치로 조사 목표를 갱신합니다.

같은 Tick에 여러 소음이 있으면 반경이 큰 소음, 거리가 가까운 소음, 사건 ID 순으로 하나를 선택합니다. 추격·공격·수색 중에는 새 소음 때문에 기억한 대상을 버리지 않습니다.

조사 위치에 도착해도 비노출 플레이어를 새 추격 대상으로 삼지 않습니다. 게이지가 낮은 상태의 공격에도 주변 NPC가 모이므로 흔적과 환경 변화는 남습니다.

### 12.6 추격·공격 — AI-06

보행보다 빠르고 질주보다 느린 속도로 추격합니다. 공격 거리에 진입하고 벽·다른 살아 있는 몸에 막히지 않으면 선딜레이를 시작합니다.

타격 Tick에 대상 생존·거리·전방 공격 각도·차단을 다시 검사합니다. 조건을 벗어났으면 빗나가고, 다른 대상으로 바꾸어 피해를 주지 않습니다. 공격은 한 대상에게 한 번이며 무적 시간·붙잡기·피격 경직은 없습니다.

선딜레이 중 대상이 시야를 벗어나도 이미 시작한 공격 주기는 진행합니다. 타격 조건을 충족하는 경우에만 피해를 주고, 주기 종료 후 기억 상태에 따라 추격·수색으로 전환합니다. 사망한 NPC의 미도래 타격은 취소합니다.

### 12.7 수색·복귀 — AI-07

시야가 끊기는 순간부터 대상의 새 위치를 추적하지 않고 마지막 목격 위치로 이동합니다. 이동 중 또는 수색 중 기억한 대상이 시야에 들어오면 노출이 해제됐더라도 추격을 재개합니다.

수색 시간이 끝나면 대상 기억을 해제하고 대기로 돌아갑니다. 이후에는 노출 상태인 플레이어만 새로 추격합니다. 대상이 사망·탈락하면 기억을 해제하고 현재 직접 보이는 신규 노출 대상을 확인합니다.

목표 지점이 도달 불가능하거나 이동 실패 제한을 넘기면 현재 도달 가능한 위치에서 조사·수색 대기 시간을 진행하고 복귀합니다. 벽 너머 현재 대상 위치로 이동 목표를 교체하지 않습니다.

이동 실패 제한은 정상적으로 이동하는 전체 소요 시간을 뜻하지 않습니다. 마지막 진행 기록보다 목표까지 남은 유효 경로 길이가 AI_PROGRESS_DELTA 이상 줄어들면 진행 시각을 갱신합니다. 그 갱신 없이 AI_MOVE_FAIL_LIMIT가 지나면 막힌 것으로 처리합니다. 새 목표를 선택할 때 진행 기준도 초기화합니다.

## 13. 맵과 배치

### 13.1 맵 콘셉트 — LVL-01

첫 맵은 작은 시가지입니다. 광장, 건물 외곽, 골목을 이용해 관찰·접근·시야 차단이 이어지게 합니다. 외형의 시대·지역·세부 미술 스타일은 특정 유료 에셋 채택을 전제로 확정하지 않습니다.

첫 블록아웃은 약 40m × 40m의 수평 경기 공간을 기준으로 합니다. 실내 진입, 옥상, 계단, 파괴 가능한 벽과 상호작용 문은 만들지 않습니다. 경기 경계는 넘을 수 없는 지형·건물로 막고 낙사 구간을 두지 않습니다.

### 13.2 공간 구성 — LVL-02

| 공간 | 초기 구성 기준 | 기능·확인 항목 |
| --- | --- | --- |
| 중앙 관찰 공간 | 약 8m × 8m의 광장 | 움직임 관찰, 여러 접근로가 교차 |
| 건물 덩어리 | 4개 내외의 불투명한 건물 블록 | 건물 모서리로 추격 시야 차단 |
| 연결 골목 | 유효 폭 3m 이상 | 몸 충돌로 한 명이 길 전체를 쉽게 막지 않는지 확인 |
| 외곽 연결로 | 서로 연결되는 이동 경로 | 중앙을 통과하지 않는 우회와 재접근 |
| 엄폐 요소 | 사람보다 높은 불투명 장애물 | NPC 눈 높이의 시야를 실제로 차단 |
| 시작 후보 | 4개 이상 | 모드별 검토한 위치 조합으로 선택 |

이 치수는 개별 공간의 블록아웃 기준이며 동시에 확정된 최종 배치도는 아닙니다. 모든 길은 실제 몸 충돌 크기와 NavMesh에서 연결돼야 합니다. 최소 두 개의 순환 경로를 두고, 승패를 가르는 장거리 일방 통로나 공격 불가능한 은신 공간은 제외합니다.

첫 맵의 장식은 이동·공격·카메라 차단 여부가 명확해야 합니다. 시각적으로 막혀 보이는데 공격이 통과하거나, 보이지 않는 장식 충돌로 공격이 막히는 상태는 수정 대상입니다.

### 13.3 시작 배치 — LVL-03

- 호스트가 검토된 위치 조합 하나를 고르고 참가자를 무작위 슬롯에 배정합니다.
- 1vs1과 4인전의 유효 조합을 각각 준비합니다. 모든 후보를 완전 무작위로 섞지 않습니다.
- 시작 캐릭터 사이에 직접 시야가 없고 근접 사거리 밖이어야 합니다.
- 각 시작점에서 보행으로 도달 가능한 NPC 무리와 시야 차단 경로가 있어야 합니다.
- 플레이어만 사용하는 빈 구역, 등장 이펙트, 특별한 발판은 없습니다.
- NPC도 캐릭터·벽과 겹치지 않는 유효한 보행 위치에 배치합니다.

필수 공간을 만족하지 못하는 Seed·조합은 시작 전에 제외합니다. 맵 준비 자체가 실패하면 전투를 시작하지 않습니다.

### 13.4 NPC 분포 — LVL-04

전체 NPC 수와 실제 밀도를 구분합니다. 초기에는 광장 및 여러 건물 주변에 나누어 배치하고 한 곳에 전부 몰아넣지 않습니다.

블록아웃 검증에서는 각 시작점 주변의 NPC 수, 주 이동 경로에서 보이는 NPC 수, 1~2분 후 밀도, NPC 처치 후 변화를 기록합니다. 총 수만 맞췄다고 위장 공간이 확보됐다고 보지 않습니다.

노출 전에는 일반 상태, 경고 구간에서는 주의 색상, 노출 중에는 원본이 낮아져도 노출 색상과 문구를 유지합니다. 초기 문구는 `노출 중 — 좀비에게 발각될 수 있습니다`입니다. `0% = 기존 추격 즉시 종료`로 안내하지 않습니다.

| 근접 명중 | 근처 타격 성공 | 명중 범위 소음 |
| 권총 발사 | 방향·거리의 단서 | 넓은 범위 소음 |
| 재장전 | 근거리에서 무기 사용 단서 | 조사 사건 없음 |
| 피격·사망 | 공통 타격 결과 | 독립적인 추가 소음 사건 없음 |
| 노출·탄약 경고 | 본인 로컬 알림 | 없음 |

평상시 NPC에게만 반복 재생되는 특징적인 소리를 붙여 플레이어를 쉽게 골라내게 하지 않습니다. AI가 듣는 반경과 실제 오디오 감쇠는 서로 다른 설정이므로 플레이어가 납득할 만큼 함께 조정합니다.

## 16. 네트워크와 권한

### 16.1 구성 — NET-01

Photon Fusion 2 Host Mode를 사용합니다. 한 참가자가 Input Authority를 가진 플레이어이면서 State Authority 역할도 수행합니다. 나머지 참가자는 자기 입력을 보내고 호스트 확정 상태를 받습니다. NPC와 경기 상태는 호스트가 관리합니다.

호스트의 창 포커스가 사라지거나 캐릭터가 관전으로 전환돼도 권한 시뮬레이션은 계속 진행해야 합니다. 백그라운드 실행 동작은 M0에서 실제 빌드로 확인하며, 이 문서 작성만으로 프로젝트 설정을 바꾸지는 않습니다.

Photon Cloud는 이 구성에서 참가자 PC 대신 NPC·전투 로직을 전부 실행해 주는 전용 게임 서버가 아닙니다. 호스트 연결·성능·판정 권한에 의존한다는 한계를 전제로 첫 플레이 가능 버전을 검증합니다. 호스트 이전과 별도 Dedicated Server 운영은 v1.0 범위 밖입니다.

### 16.2 권한 표 — NET-02

| 데이터·행동 | 최종 판정 | 클라이언트 역할 |
| --- | --- | --- |
| 방 상태·참가 슬롯·시작 | 호스트 | 준비·시작 요청 및 표시 |
| 플레이어 이동·몸 방향 | 호스트 | 입력 전송, 본인 이동 예측·표시 보정 |
| 카메라 | 본인 로컬 | 조준에 필요한 방향 입력만 전달 |
| 공격 승인·타격·피해·사망 | 호스트 | 입력·예측 연출, 확정 결과 반영 |
| 탄약·재장전 | 호스트 | UI와 무기 연출 표시 |
| 노출·NPC 감각·추격·공격 | 호스트 | 상태·이동·모션 표시 |
| 생존 인원·시간·결과 | 호스트 | 원본 기반 표시 |

클라이언트가 보내는 것은 이동·버튼·조준 의도입니다. `누구를 맞혔다`, `즉사다`, `탄약이 늘었다`는 결과를 신뢰하지 않습니다. 호스트는 속도·회전·행동 잠금·발사 간격·탄약·공간 판정을 확인합니다.

### 16.3 Tick 결산 — NET-03

같은 Tick의 캐릭터를 순서대로 죽여 상대 공격이 사라지지 않도록 다음 논리 순서를 유지합니다.

1. 경기 활성 상태·시간·탈락·입력 유효성과 입력 우선순위를 확인하고 이번 Tick의 이동·행동 의도를 정합니다.
2. 의도에 맞는 이동 속도·회전 상한을 적용하고 이 Tick의 판정용 공간 상태를 정합니다. 유효한 근접 시작 의도에는 이때부터 감속을 적용하고, 조준 의도에는 조준 이동을 적용합니다.
3. 플레이어 행동 승인, 노출 증가·감소·전환과 행동 타이머를 갱신합니다.
4. NPC 인지와 행동 전환을 평가합니다. 새로 시작한 NPC 이동은 다음 이동 갱신에서 진행합니다.
5. 이번 Tick에 도래한 유효 근접·발사·NPC 타격을 수집합니다. 후보 대상의 생존 여부는 피해 결산 전 기준입니다.
6. 피해를 함께 결산하고 사망·공격 취소·생존 인원을 갱신합니다.
7. 승리·전멸·시간 초과를 한 번만 판정합니다.
8. 확정 상태와 사건을 참가자에게 전달합니다.

제한 시간 경계에서는 새 이동·새 공격을 시작하지 않고, 경계 시각까지 도래한 기존 공격만 결산합니다. 이전 Tick에 이미 죽은 캐릭터의 미완료 타격은 유효 공격으로 수집하지 않습니다.

이 순서는 게임 규칙입니다. Fusion을 사용한다고 자동으로 상호 공격 결산이 구현된 것으로 보지 않습니다.

### 16.4 예측·재시뮬레이션 — NET-04

본인 이동과 일부 조작 연출은 반응성을 위해 예측할 수 있습니다. 피해·사망·승패는 호스트 확정 전 최종 결과로 표시하지 않습니다. NPC NavMesh와 난수 AI는 각 클라이언트에서 독립 실행하지 않습니다.

입력 Sequence·공격 ID·사건 ID·라운드 ID로 중복 실행을 구분합니다. 예측 재시뮬레이션이나 중복 메시지 때문에 탄약·노출·피해·사운드가 여러 번 적용되지 않아야 합니다. 라운드가 바뀌면 이전 라운드의 입력·사건은 폐기합니다.

### 16.5 지연 보정 기준 — NET-05

v1.0 최초 기준은 **호스트 타격 Tick의 현재 위치·몸 방향**입니다. 플레이어가 보던 과거 위치로 되돌리는 명중 보정은 초기 완료 범위에 넣지 않습니다. Fusion의 예측·보간을 사용하는 것과 과거 히트박스 명중 검사를 적용하는 것은 구분합니다.

실제 RTT·패킷 손실 환경에서 후방 판정과 사격 불일치를 기록합니다. 보정을 도입하려면 거리·시야·후방 방향을 어느 동일 시각으로 평가할지 별도 변경안을 작성합니다. 거리만 과거로 돌리고 후방 방향은 현재로 검사하는 식의 기준 혼용은 허용하지 않습니다.

공식 SDK가 지연 보정 기능을 제공한다는 사실은 우리 게임에 적용·검증됐다는 근거가 아닙니다.

## 18. 예외와 오류 처리

### 18.1 방·로딩 — ERR-01

| 상황 | 처리 | 사용자에게 필요한 안내 |
| --- | --- | --- |
| 코드 형식 오류 | 네트워크 요청 없이 수정 유도 | 입력 형식 |
| 방 없음·만료 코드 | 입장 중단, 입력 화면 유지 | 방을 찾을 수 없음 |
| 정원 초과 | 슬롯·캐릭터 생성 없이 거절 | 방이 가득 참 |
| 로딩·경기·결과 중 입장 | 거절, 외부 관전으로 바꾸지 않음 | 현재 입장할 수 없음 |
| 빌드·설정 버전 차이 | 준비 전 거절 | 같은 버전이 필요함 |
| 생성 코드 반복 충돌 | 재생성 상한 후 생성 실패 | 다시 만들기 |
| 생성·입장 제한 시간 초과 | 시도 종료, 로컬 연결 상태 정리 | 연결 지연·재시도 |
| 생성·입장 취소 | 진행 중 요청 무효화 | 이전 화면 복귀 |
| 취소 후 늦은 성공 응답 | 자동 입장하지 않고 해당 시도 정리 | 취소 상태 유지 |
| 로딩 실패·제한 시간 초과 | 시작 취소, 남은 참가자 대기실 복귀 | 로딩 실패 참가자·다시 준비 |
| 시작 대기 중 참가자 이탈 | 카운트다운 취소, 준비 초기화 | 참가자 변경 |
| 호스트 이탈 | 세션 중단 | 방 종료·타이틀 복귀 |

요청 중 버튼 중복 입력을 막고 시도 ID로 늦은 응답을 구분합니다. 원시 예외·AppId·스택 트레이스를 제품 UI에 표시하지 않고 개발 로그에 남깁니다.

### 18.2 연결 유실 — ERR-02

명시적인 나가기·확정된 SDK 연결 종료와, 짧은 패킷 지연·손실을 구분합니다. 일반 참가자의 확정 종료는 탈락 처리합니다. 종료가 확정되지 않은 연결 유실은 대기 한도 안에서 관찰하며, 매 패킷 누락을 즉시 사망으로 처리하지 않습니다.

연결 유실이 감지된 동안 새 공격을 임의로 생성하거나 마지막 공격 입력을 반복하지 않습니다. 새 유효 이동 입력이 없음을 확정한 캐릭터는 중립 입력으로 전환합니다. 캐릭터는 경기 안에 남아 피해를 받을 수 있고 시간도 계속 흐릅니다.

유실 대기 중 연결이 유지·정상화되면 최신 확정 상태를 받습니다. 이미 종료된 세션에 다시 가입해 캐릭터를 복구하는 재접속 기능과는 구분합니다. SDK의 확정 종료 대기와 게임의 대기를 중복으로 두 번 적용하지 않도록 구현 시 실제 설정과 콜백을 맞춥니다.

호스트 연결을 잃어 권한 판정을 이어갈 수 없으면 세션 중단입니다. 이미 확정 결과를 수신했다면 그 결과를 보존하며, 결과를 받지 못한 클라이언트가 승자를 추측하지 않습니다.

| 상황 | 처리 |
| --- | --- |
| 공격 대상이 타격 전에 사망 | 타격 후보에서 제외, 시체 관통 규칙 적용 |

경기 중 위치 보정은 벽을 통과하는 이동 능력이 아닙니다. 맵·충돌 오류를 복구하기 위한 예외이며 반복 발생하면 진행 차단 결함으로 취급합니다.

## 19. 성능·개발 환경 기준

### 19.1 검증 목표 — NFR-01

초기 PC 성능 목표는 1920×1080에서 60FPS, 호스트 60Hz 시뮬레이션입니다. 최소 하드웨어 사양은 아직 실측하지 않았으므로 CPU·GPU 제품명을 최소 사양으로 발표하지 않습니다.

4인·NPC 30마리에서 호스트와 원격 클라이언트 각각 렌더 프레임 시간, 호스트 Tick 처리 시간, 대역폭, GC 할당을 측정합니다. 호스트 Tick 처리 시간 P95가 1 Tick 예산인 약 16.7ms를 넘지 않는 것을 초기 목표로 삼되, 측정 PC 사양·해상도·빌드·샘플 시간을 반드시 함께 기록합니다.

에디터에서만 잘 동작했다는 이유로 빌드 성능을 통과 처리하지 않습니다. 호스트가 사망·관전 중이어도 NPC와 판정 성능을 다시 확인합니다.

### 19.2 네트워크 조건 — NFR-02

| 조건 | 확인 목적 |
| --- | --- |
| 실제 서로 다른 PC, 낮은 지연 | 기본 연결·권한·장치 차이 |
| RTT 약 100ms | 일반적인 지연에서 이동·후방·사격 체감 비교 |
| RTT 약 200ms | 불일치 사례와 플레이 가능 범위 관찰 |
| 지터 약 20ms | 보간·입력 변화의 불안정 확인 |
| 패킷 손실 약 1% 및 3% | 입력·사건 중복 방지, 상태 회복·종료 확인 |
| 호스트·클라이언트 이탈 | 세션 중단·일반 탈락·관전 호스트 처리 |

이 표는 실행해야 할 조건이며 통과 결과가 아닙니다. 시뮬레이터 지연이 편도인지 RTT인지 구분해 기록합니다. 고지연에서 판정이 완벽히 일치한다는 합격 조건을 만들지 않고 사례·원인·허용 여부를 검토합니다.

### 19.3 구현 착수 시 고정할 환경 — NFR-03

Unity 버전, Fusion 2의 정확한 패키지 버전, 입력 백엔드, 공통 Photon AppId·리전, 빌드 식별자, 설정 버전, 측정 PC 사양은 실제 프로젝트 생성·SDK 호환성 확인 후 별도 환경 명세에 기록합니다.

이는 미정인 게임 규칙이 아니라 검증 전의 구현 환경 정보입니다. 존재하지 않는 프로젝트 버전이나 성능 수치를 이 문서에서 검증된 사실처럼 만들어 적지 않습니다. Photon 요금·트래픽 한도는 테스트 규모를 늘릴 때 공식 안내로 다시 확인하며 무료 무제한 운영을 전제하지 않습니다.

### 23.2 v0.5와의 관계

v0.5의 수동 위장·최후 생존·후방 즉사·권총·노출·재은신·관전·재경기를 계승합니다. PC와 네트워크 구성을 확정하고, 초대 방·시가지·근접 대상 선정·정렬 후 발사를 구체화했습니다.

기존의 '전방 범위'와 '무기 궤적' 혼재는 부채꼴 단일 타격 규칙으로 통일했습니다. 문서에 없는 공개 매칭·전용 서버·모바일 조작을 이미 승인된 기능으로 확대하지 않습니다.

### 23.3 변경 절차

수치 조정은 항목 ID·변경 전후 값·목적·비교 결과를 남깁니다. 후방 즉사 제거, 다른 승리 조건 도입, 조준만으로 노출 증가, 몸 방향과 무관한 즉시 발사, 대상별 어그로 예외, 신규 모드·플랫폼 추가는 기능·규칙 변경으로 별도 판단합니다.

실측 전인 밸런스·성능·공간 배치는 '검증 완료'로 바꾸지 않습니다. 실제 프로젝트 환경 정보는 M0에서 고정합니다. 후속 목표는 첫 전투 결과를 확인한 뒤 별도 개정안으로 작성합니다.
