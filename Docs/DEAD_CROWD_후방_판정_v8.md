# 후방 즉사 판정 완화 — 실행 규칙 v8

2026-11-02. 뒤에서 공격해도 즉사하지 않는다는 플레이 피드백에 따른 조정입니다. 상세 기획 v1.0의 MEL-04 및 기존 QA-030/031보다 아래 변경을 우선합니다. 최종 밸런스는 아직 플레이로 검증하지 않았습니다.

| 항목 | 이전 | 변경 |
| --- | --- | --- |
| 후방 범위 | 정후방 ±50도, 전체 100도 | 정후방 ±80도, 전체 160도 |
| 대상 전방 기준 경계 | 공격자가 130~180도에 위치 | 공격자가 100~180도에 위치, 100도 포함 |
| 선딜레이 중 대상 회전 | 타격 순간 후방이 아니면 일반 피해 | 공격 시작에 후방으로 잡힌 같은 대상은 해당 공격에서 후방 인정 |
| 타격 순간 후방 진입 | 후방 인정 | 유지 |
| 거리·공격 방향·차단·단일 대상 선정 | 타격 순간 검사 | 유지 |

## 원인과 변경 방식

기존 코드는 실제 타격 시점에만 대상의 몸 방향을 검사합니다. 공격 소음은 공격 시작에 발생하고 NPC는 이 소음을 같은 Tick에 처리하여 조사 이동·회전을 시작할 수 있습니다. 따라서 0.3초 선딜레이 동안 후방 범위를 벗어나는 것이 가능한 구조였습니다. 이 구조가 사용자의 개별 실패 사례와 일치하는지는 플레이 로그로 확인하지 않았습니다.

공격 승인 시 기존 근접 대상 선택 함수를 사용해 거리·전방 공격 각도·차단 조건을 만족하는 가장 가까운 대상을 확인합니다. 그 대상의 후방에 있다면 해당 공격의 후보로만 기록합니다. 플레이어와 NPC 대상에 동일한 규칙을 적용합니다.

타격 시에는 대상을 다시 선택합니다. 실제 명중 대상이 기록한 후보와 같으면 선딜레이 중 회전했어도 후방 즉사로 처리합니다. 명중 대상이 바뀌었으면 기존 후보의 판정을 전달하지 않고 새 대상의 현재 방향만 검사합니다. 타격 시 공격 범위 밖으로 이동했거나 벽·다른 캐릭터가 가리면 여전히 빗나갑니다. 시작 때 범위 밖이었다가 타격 시 들어온 대상은 현재 방향으로 판단합니다.

후방 피해는 고정 100이 아니라 현재 `MAX_HP`를 사용하므로 최대 체력 변경 후에도 즉사를 유지합니다. 일반 근접 피해, 공격 거리, 전방 공격 각도, 선딜레이, 주기와 NPC AI는 변경하지 않습니다. 소음 반응 자체도 유지합니다.

후보는 서버/로컬 솔로 권위에서만 사용하고, 매 공격 시작·판정 완료·라운드 초기화 시 정리합니다. 클라이언트가 보낸 후방 성공 여부를 신뢰하지 않습니다. 규칙 변경을 구분하기 위해 실행 프로토콜을 `dead-crowd-development-8`로 올립니다.

## 커스텀과 확인

활성 `GameSettings` Inspector에서 다음 값을 조정한 뒤 새 세션을 시작합니다.

- `BACK_HALF_ANGLE`: 기본 80도. 90도는 정확히 뒤쪽 반원까지이며 90도를 넘기면 앞쪽 측면도 포함합니다.
- `BACKSTAB_WINDUP_GRACE`: 기본 켜짐. 끄면 타격 순간의 후방 여부만 검사합니다.
- 두 값을 50도·꺼짐으로 바꾸면 기존 후방 판정 규칙으로 비교할 수 있습니다.

`DEAD CROWD > Development > Verify Backstab Rules`는 양쪽 경계, 경계 밖, 높이 무시, 정후방, 같은 위치, 대상 변경 및 선딜레이 회전 유예의 순수 규칙을 검사합니다. Windows 빌드에서도 이 검사를 실행합니다. 이 결과는 실제 이동·애니메이션·온라인 지연을 포함하는 플레이 QA와 구분합니다.

실제 플레이 및 온라인 회귀 QA는 이번 작업에서 진행하지 않습니다. 공격 로그에는 `back`, `opening`, `targetAngle`을 남겨 후속 확인 시 실제 방향과 유예 적용 여부를 구분할 수 있습니다.

작업 검증 결과: Unity 컴파일, 기본 설정에서 순수 규칙 검사 11개, 저장된 UI 참조 검사, Windows Development 빌드가 성공했습니다. 로그는 `Logs/BackstabV8Build.log`, 실행 파일은 `Builds/Development/DEAD-CROWD.exe`입니다. 실제 플레이 체감과 네트워크 지연 상황은 미검증입니다.
